# GO Flow — лендинг для специалистов с админкой

Нужен PHP 8.0+ с `pdo_sqlite` (есть на любом обычном хостинге, в том числе REG.RU). Собирать ничего не нужно, отдельная база данных тоже не нужна: SQLite-файл создаётся сам.

## Что внутри

| Адрес | Что это |
|---|---|
| `/go-flow/` | Лендинг: открытые проекты из базы, фильтр по стеку, анкета |
| `/go-flow/python/`, `/go-flow/go/`, … | Страницы направлений для SEO и рекламы: свой заголовок, title, canonical, проекты направления сверху |
| `/go-flow/p/<slug>` | Страница проекта: полная карточка, отклик с привязкой к проекту, OG-превью для Telegram |
| `/go-flow/r/<code>` | Короткая ссылка для канала: считает клик и ведёт на проект или лендинг с UTM |
| `/go-flow/sitemap.xml` | Карта сайта: лендинг, направления, открытые проекты |
| `/go-flow/admin/` | Админка: проекты, заявки, ссылки для каналов, источники и CPA |
| `/go-flow/api/projects.php` | Открытые проекты в JSON (для бота, виджетов) |
| `/go-flow/api/apply.php` | Приём анкеты (POST JSON) |

## Установка

1. Загрузите содержимое папки на хостинг в каталог `go-flow`.
2. Проверьте, что в архиве есть `config.php`. Если его нет, скопируйте `config.sample.php` в `config.php` и заполните.
3. Папка `data/` должна быть доступна PHP на запись. Там лежит база.
4. Откройте `https://murx.io/go-flow/` — база и примеры проектов создадутся при первом заходе.
5. Войдите в `https://murx.io/go-flow/admin/`.

**Apache** (REG.RU и большинство хостингов): красивые адреса и закрытие служебных папок уже настроены в `.htaccess`.

**Чистый nginx без Apache** — добавьте в конфиг сайта:

```nginx
location ~ ^/go-flow/(lib|data)/ { deny all; }
location ~ ^/go-flow/(config|config\.sample|sync)\.php$ { deny all; }
location ~ \.(sqlite|md)$ { deny all; }
rewrite ^/go-flow/p/([a-z0-9-]+)/?$ /go-flow/project.php?slug=$1 last;
rewrite ^/go-flow/r/([a-z0-9]+)/?$ /go-flow/r.php?c=$1 last;
```

Если правила переписывания включить нельзя, поставьте в `config.php` `'pretty_urls' => false`: ссылки станут вида `project.php?slug=…`.

**После установки проверьте:** `https://murx.io/go-flow/data/goflow.sqlite` и `https://murx.io/go-flow/config.php` должны отдавать 403 или 404.

## config.php

| Ключ | Что делает |
|---|---|
| `demo` | `true` — жёлтые пометки «подтвердить». Перед запуском поставить `false` |
| `base_url` | Абсолютный адрес, например `https://murx.io/go-flow`. Пусто — определяется сам |
| `db_path` | Путь к базе. Надёжнее вынести за пределы публичной папки |
| `admin.email`, `admin.password_hash` | Вход в админку. Новый хэш: `php -r "echo password_hash('НОВЫЙ_ПАРОЛЬ', PASSWORD_DEFAULT), PHP_EOL;"` |
| `ym_id`, `vk_pixel_id` | Яндекс Метрика и пиксель VK |
| `tg_url` | Канал или бот с проектами |
| `cabinet_url` | Кабинет GO Flow для экрана «Проходит» |
| `notify.tg_bot_token`, `notify.tg_chat_id` | Уведомления о новых заявках в Telegram |
| `platform.*` | Синхронизация проектов с платформой |
| `platform.register_url` | Создание аккаунта на платформе для прошедших скоринг: кнопка «Войти в кабинет» ведёт по одноразовой ссылке из ответа |
| `scoring` | Переопределение правил скоринга (см. `lib/scoring.php`, `docs/GO-Flow-бриф-скоринг.docx`) |

## Админка

- **Проекты.** Создание, правка, статусы (черновик / открыт / пауза / закрыт). На сайте видны только открытые. У закрытого проекта страница остаётся доступной с плашкой «набор закрыт» и похожими проектами, чтобы старые ссылки в каналах не вели в пустоту.
- **Заявки.** Список с фильтрами по скорингу, статусу, направлению, проекту, каналу и датам. В карточке заявки: ответы, причины скоринга, источник, статус и заметки. Есть выгрузка в CSV.
- **Ссылки для каналов.** На каждый канал, чат или аутрич-рассылку создаётся короткая ссылка. Админка сразу собирает текст поста для Telegram по проекту. Для платного размещения в пост добавляется строка «Реклама … erid».
- **Источники и CPA.** По каждому `utm_source` и кампании: клики, уникальные посетители, шаг 1, анкета целиком, прошли скоринг, расход, CPL и CPA.

## Как считаются источники

1. Человек кликает `/r/abc123`. Клик записывается, человек попадает на проект с `utm_*` и `lc=abc123`.
2. UTM сохраняются в sessionStorage и уходят с анкетой. Источник фиксируется по шагу 1, шаг 2 его не перетирает.
3. Отчёт сводит клики по ссылкам и анкеты по UTM. Расход берётся из поля «Стоимость размещения» у ссылок.

Ссылки с UTM, собранные вручную (без `/r/`), тоже попадают в отчёт, только без счётчика кликов.

## API платформы (задел)

Когда у платформы GO Flow появится API, включите в `config.php`:

```php
'platform' => ['enabled' => true, 'url' => 'https://…/api/v1/requests?status=open', 'token' => '…', 'timeout' => 15],
```

Синхронизация запускается кнопкой в админке или по cron:

```
*/30 * * * * php /home/USER/www/murx.io/go-flow/sync.php
```

Как работает синхронизация:
- новые запросы создаются;
- изменённые обновляются;
- исчезнувшие из ответа закрываются;
- у проекта с флажком «Не перезаписывать при синхронизации» ручные правки сохраняются.

Формат ответа, который ждёт лендинг, описан в `lib/projects.php` над функцией `platform_fetch()`. Если у платформы будет другой формат, правится одна функция: маппинг полей в `platform_sync()`.

## SEO

- У страниц проектов есть разметка `JobPosting` (schema.org): ставка, стек, удалёнка, дата публикации.
- У страниц направлений свой title, описание и canonical.
- Добавьте в `robots.txt` в корне сайта строку `Sitemap: https://murx.io/go-flow/sitemap.xml` и отправьте карту сайта в Яндекс Вебмастер.

## Перед запуском

- [ ] `demo => false`, примеры карточек заменены на реальные проекты
- [ ] Пароль админки сменён на новый (хэш в `config.php`)
- [ ] Сервер с базой находится в РФ (152-ФЗ, локализация данных)
- [ ] `privacy.html` и `consent.html` заменены текстами юриста, подано уведомление в РКН
- [ ] Указаны `ym_id`, `tg_url`, при желании — `notify` для уведомлений в Telegram
- [ ] `data/` и `config.php` закрыты снаружи (проверить по адресу)
