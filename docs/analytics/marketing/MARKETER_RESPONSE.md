| paid_social (TG-посты, VK Ads) | лендинг | регистрация | верификация пройдена | capture ЛОКАЛЬНО; классификация РАЗРЫВ DT-01; лендинг → регистрация НЕ ПРОВЕРЕНО DT-03 |

| job_board (hh вакансии, биржи) | лендинг | регистрация | верификация пройдена | DT-02; сохранение ссылок на площадке ВОПРОС |
| content (Habr, vc) | лендинг | регистрация | верификация пройдена | DT-02 |

### 1.2 Заказчики

Атрибуция клиентских лидов **не подтверждена** (ТРЕБОВАНИЕ пакета). Фактически известно: клиентов на пилот приводит владелец через свои связи. Это оффлайн-путь, UTM к нему не применимы.

| Точка входа | Целевое действие | Качественный результат | Статус |
|---|---|---|---|
| связи владельца, CSM | ручное заведение клиента | заявка → первое продвижение кандидатуры → подключение | ПРЕДЛОЖЕНИЕ: поле источника при ручном заведении (`owner_network`, `csm`, `partner`); не угадывать по оффлайн-признаку |
| форма демо / заявки на сайте | заявка | как выше | ВОПРОС В7: существует ли; если да, DT-10 |
| внешние лендинги для заказчиков | заявка | как выше | ВОПРОС В7 |

Напоминание из пакета: заявки не равны местам, клиентский аккаунт не равен корпоративной группе, согласованная дата начала не равна фактическому выходу.

## 2. Стандарт UTM (ПРЕДЛОЖЕНИЕ)

Правила пакета принимаю полностью (строчные ASCII, `_`, до 100 символов, без персональных данных, click id только от платформ). Уточнения:

- **utm_campaign** = `{год}q{квартал}_{аудитория}_{сегмент}_{волна}`, аудитория `specialists` или `customers`. Кампания описывает стек и волну, а не площадку: одна кампания идет через несколько каналов, и это позволяет сравнить каналы внутри одного стека. Примеры: `2026q4_specialists_java_launch`, `2026q4_specialists_sa_launch`, `2026q4_specialists_go_launch`, `2026q4_specialists_frontend_launch`, `2026q4_specialists_referral`, `2026q4_specialists_godigital_base`.
- **utm_source** = площадка: `telegram`, `telegram_dm`, `vk_ads`, `yandex`, `hh`, `habr`, `vc`, `godigital_crm`, `specialist_referral`, код биржи.
- **utm_adgroup** = группа: код TG-канала, база (`base_tgchats`, `base_hh_resume`), вакансия; в Директе макрос `{gbid}`, в VK Ads макрос (синтаксис сверить со справкой). Алиасы `ad_group`, `gbid` не используем.
- **utm_creative** = вариант текста/картинки; в Директе `{ad_id}`. Алиасы `creative`, `ad_id` не используем.
- **utm_content** = вариант размещения (`post_a`, `msg_a`, `vacancy_a`).
- **Тестовые ссылки**: `utm_medium=test`, кампания с префиксом `test_`, исключаются из KPI (DT-12).
- **Сокращатели**: не использовать, пока DT-05 не подтвердит, что метки доходят.
- **Названия TG-каналов-площадок** кодировать (`tgch_java_a`), если название раскрывает договоренности.

Словарь medium: `UTM_DICTIONARY.csv`. Проверка ссылок перед публикацией: `python validate_utm.py CAMPAIGN_MATRIX.csv`.

## 3. Макет отчета по качеству привлечения (ПРЕДЛОЖЕНИЕ)

Шаблон колонок: `REPORT_MOCKUP_SPECIALISTS.csv`. Принципы:

1. Два среза, **first_touch** и **last_significant_touch**, рядом, никогда не суммируются.
2. Строка: срез → канал → source → кампания → креатив → когорта по неделе регистрации.
3. Каждая веха: N и доля с явным знаменателем (`n/N` от регистраций).
4. Зрелость: окна 7/14/30 дней от регистрации. Незрелая когорта показывает «мало времени», не 0%. Предлагаемые окна: резюме заполнено за 7, отправлено на проверку за 14, верификация за 30 (ВОПРОС В9).
5. Малые N показываются, но победитель не объявляется. Порог минимального N согласовать отдельно, сейчас не задаю.
6. Контрольные строки: `unknown` (absent / rejected), `exclude_test`, legacy-активации отдельно.
7. Время свежести данных на каждой строке.
8. Расходы и стоимость верифицированного специалиста только после согласования источника (DT-13, В3). Сейчас колонки пустые.
9. Ручной блок аутрича (отправлено, ответили, перешли) отдельно от системных N, с пометкой «ручной учет».

Для заказчиков отчет не строим, пока не закрыт раздел 1.2.
